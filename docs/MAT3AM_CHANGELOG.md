# سجل تعديلات مطاعم (MAT3AM)

## 1 — الدخول والمصادقة وخادم الـ API (مطاعم/backend)

- **دخول المطوّر `dev` / `dev@123`**: يبقى متاحاً في أي وقت (قبل وبعد تهيئة `MAT3AM_APP_USERS`) دون رفض لمجرد وجود مستخدمين في القاعدة. يمكن تغيير الاسم/الرمز عبر `MAT3AM_INITIAL_DEV_LOGIN` و `MAT3AM_INITIAL_DEV_PIN`.
- **تمت إزالة** منطق «رفض dev بعد التهيئة» من `api_server.py` الحالي في مجلد مطاعم.
- **التحقق من الخادم**: افتح `http://127.0.0.1:2288/__whoami__` — يجب أن يظهر سطر **`MAT3AM_API=1 DEV_LOGIN_ALWAYS=1`**. إن لم يظهر فالمنفذ 2288 يشغّل نسخة API أخرى (مشروع آخر أو ملف قديم): أوقف العملية وشغّل `run_api.bat` أو `restart_from_zero.bat` من جذر مجلد **مطاعم**.
- **منافذ التطوير الاعتيادية**: واجهة Vite (مثلاً 9999 حسب `vite.config.ts`) + API على **2288** (`XTRA_API_PORT`). طلبات `/api` من الواجهة تُمرَّر بالبروكسي إلى 2288.
- **تهيئة TBL020**: زر التهيئة يدرج أنماط الفواتير الستة؛ قاعدة فارغة تُجرَّب إدراجاً مباشراً ثم نسخاً من قالب عند الحاجة.

## 2 — القوائم والتبويبات (واجهة)

- **الشريط الجانبي**: ترتيب محاسب — تقارير قبل التكاليف؛ جرسون — «الطاولات» ثم «طلب للطاولة» ثم «طلب سريع (بار)».
- **إعدادات النظام**: أقسام بعناوين — المكان والصالة، القوائم والمبيعات، التكاليف والتعريفات، النظام والصيانة.

## 3 — جرسون الطلبات والمطبخ

- عند **`POST /api/restaurant/invoices`** لنوع `table` مع `sessionId` يُنشأ تلقائياً صف في **`orders`** (ملف JSON) لشاشة المطبخ، مع `tableId` و`generalOrder` و`invoiceId`.
- **إلغاء من الجرسون**: `PATCH .../orders/{id}/status` بـ `cancelled` — مسموح فقط إن كانت الحالة `pending` (قبل «بدء التحضير»).
- **الواجهة**: زر «طلب عام (للجميع)»، حذف كل بنود كرسي (× تحت الكرسي)، حذف سطر من السلة، قائمة «طلبات مُرسلة» مع إلغاء إن أمكن.

## 4 — نسبة الخدمة في الكاشير (POS)

- في **نقطة البيع** (`PosPlaceholder`): حقل «نسبة الخدمة لهذه الفاتورة %» + زر «استخدام الافتراضي» (من `/api/pos/policy`). يُصفَّر التعديل عند إفراغ السلة.
