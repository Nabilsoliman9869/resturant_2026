# نقطة مرجعية — 2026-05-11

## ما الذي يُوثَّق هنا؟

هذا الملف يشرح **أين وصل المشروع** قبل البدء بتوسعة تجربة الموبايل، حتى لا يضيع السياق أو يُفقد العمل.

### ما تم تنفيذه تقريباً حتى هذه اللحظة

1. **Shared Terminal Mode** — جهاز مشترك بين الجرسونات مع PIN، وحماية على السيرفر للمسارات الحسّاسة.
2. **Hybrid v2** — نافذة زمنية منزلقة + خروج كامل بعد إهمال + Step-Up لعمليات خطرة + تبديل مستخدم عند PIN مختلف.
3. **تحسين الأداء** — تخزين مؤقت لإعدادات الطرفية وعدم تشغيل DDL على كل طلب (تقليل ضغط قاعدة البيانات).
4. **واجهات**: `TerminalLockContext`, `PinOverlay`, `InlinePinConfirm`, صفحة إعدادات نقطة البيع، ربط جزئي على الطاولات والطلبات.

### ما لم يُنفَّذ بعد (حسب الخطة المشتركة)

- تطبيق «كامل» للموبايل كـ PWA وresponsive عميق لكل الشاشات.
- إعدادات **لكل جهاز على حدة** (موبايل بدون PIN، شاشة صالة مع PIN) — مذكورة كنموذج تقني للمرحلة القادمة.
- تلميع شاشة نقطة البيع للشاشات الصغيرة — المخطط أدناه في المحادثة، التنفيذ لاحقاً.

### الرجوع للخلف (Rollback) محلياً

بعد كل commit/tag موثَّق:

```bat
cd /d "المسار\مطاعم"
git log --oneline -5
git checkout TAG_OR_COMMIT -- .
```

أو استعادة فرع كامل:

```bat
git checkout main
git reset --hard TAG_OR_COMMIT
```

**تحذير**: `reset --hard` يمسح تغييرات غير مُكمَّلة — احفظ عملك قبلها.

### GitHub

بعد `git push origin main` (أو الفرع المعتمد)، النسخة على السحابة تطابق الـcommit الموسوم.

## الموبايل — ملخص بلا تعقيد (للمتابعة)

- **لا نغيّر قاعدة البيانات كلها**؛ نفس النظام يعمل على المتصفح في الجوال.
- **الموبايل الشخصي للجرسون**: غالباً **بدون PIN** لأنه جهازه.
- **شاشة الصالة المشتركة**: تبقى **مع PIN** كما اتفقنا.
- **الدخول للطلب**: من **شرائح الطاولات** زر يفتح نفس صفحة الطلب لكن بعرض مناسب للجوال (تدريجياً).

### نقطة البيع «الضخمة» على الجوال — الفكرة الواحدة

لا نعرض كل شيء دفعة واحدة:

1. **الأعلى**: بحث سريع + اسم الطاولة.
2. **الوسط**: مجموعات الأصناف كشرائح أفقية قابلة للسحب (مثل قصص انستغرام).
3. **تحتها**: شبكة أصناف كبيرة اللمس (صورة أو اسم + سعر).
4. **الأسفل الثابت**: السلة مع زر «إرسال للمطبخ» — يبقى ظاهراً أثناء التمرير.

الإضافات والخيارات تظهر **في نافذة منبثقة** عند لمس الصنف، وليس كل الخيارات على الشاشة الرئيسية.

بهذا نحافظ على نفس المنطق والـAPI؛ التغيير غالباً **شكل وتخطيط** وليس «برنامج ثاني».
